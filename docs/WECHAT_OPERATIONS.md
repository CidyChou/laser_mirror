# 微信广告与运营接入

本次参考 block-escape 的广告缓存、领奖校验、通关插屏和游戏圈接入方式，为《光线急转弯》接入同类能力。配置集中在 [`templates/wechat/operations.json`](../templates/wechat/operations.json)，没有复制 block-escape 的广告 ID 或专属 openlink。

目前所有广告 ID、游戏圈专属参数均留空，不产生真实广告请求。普通「推荐游戏」使用微信官方通用组件常量，在支持 `wx.createPageManager` 的微信环境中即可使用。游戏圈开通、帖子发布和流量主申请仍由本游戏的 MP 后台完成。

## 广告位置

| 位置 | 配置键 `ads.*` | 玩家获得 / 展示时机 |
| --- | --- | --- |
| 爱心用完页、游戏内「补给提示」 | `hearts` | 完整观看视频，增加 5 颗爱心，最多 5 颗；保留当前镜面布局 |
| 选关页金币栏「＋」、游戏内「补给提示」 | `coins` | 完整观看视频，增加 60 金币 |
| 游戏内「补给提示」 | `hint` | 完整观看视频，调整一处镜面 / 分光器 / 集光器；普通关卡有待调整的解法时提供 |
| 通关页 | `double` | 再领一份本关通关金币；原有金币先照常保存，翻倍不要求继续下一关 |
| 通关页点击「下一关」或「选择关卡」 | `interstitial` | 首次完成第 3、8、13、18…个新关卡时尝试；未就绪立即跳过 |
| 选关列表底部独立区域 | `menu` | 原生模板广告；为广告预留区域，关卡列表不会被盖住 |

`hearts`、`coins`、`hint`、`double` 需要创建**激励视频广告位**。可以先共用一个实际广告位，同一 ID 只创建一个 SDK 实例和一份在途下载；独立 ID 有利于在流量主后台区分各场景收益。`interstitial` 需要**插屏广告位**，`menu` 需要**原生模板广告位**，不能混填广告类型。

原生模板请采用 **20:7、320×112 逻辑像素**的横向模板；若后台选择其他尺寸，同步修改 `menuTemplate.width/height`。组件报告的实际尺寸超过预留区域时销毁并跳过。窗口放不下时不展示。进入关卡、设置、补给、运营页面、后台或其他广告时隐藏原生广告。玩家关闭模板后，本次游戏不再重新弹出。

没有使用停止维护的旧 Banner 接口；采用 `wx.createCustomAd`。不在启动、发射、旋转镜面或失败时自动播放视频。

## 没有广告 ID 时

- 爱心用完可用金币购买：20 金币 / 颗，缺 5 颗时 80 金币补满；余额不足补满但够买多颗时，提供对应数量的购买按钮。已满不扣款，不出售用不上的爱心。
- 每 10 分钟自然恢复 1 颗，最多 5 颗；离线也会恢复。移除不限次数的免费补满 / 免费恢复按钮，保留金币购买、自然恢复和返回选关。
- 新玩家获得一次 40 金币起始储备；原有金币存档不削减。普通关首通 6～14 金币、章节挑战为对应普通关的两倍，重玩不重复发币，详见 [金币与爱心数值](ECONOMY.md)。
- 金币视频、免费提示视频、通关翻倍、插屏和原生模板根据各自 ID 和 SDK 能力启用，留空的项目不调用广告 SDK。
- 提示也支持花费 **60 金币**；未配置视频不影响金币提示、普通试射和新手引导。金币不足时提示按钮不可用。
- 普通关卡提示使用本项目当前 200 个棋盘验证过的解法，每次只调整一个物件；章节动态挑战保留其原有玩法说明。改关卡后执行 `npm run generate:hints` 更新解法；棋盘指纹不匹配时不提供旧提示。

## 激励与插屏规则

金币、视频提示、通关翻倍共用每天 **8 次**额外领奖次数，由 `rewards.dailyBonusLimit` 控制；爱心恢复单独处理，避免玩家因额度用完无法继续。额度按设备本地自然日保存。视频提前关闭、缺少明确完成状态、加载失败、重复回调、切换关卡或销毁游戏均不扣额度、不发奖。

金币视频另限每天 **3 次**；余额达到 **200** 时暂停提供额外金币视频。正常通关所得不受此门槛限制，符合条件的视频完整发放 60 金币，不截成零头。选关页右上角持续显示余额，点击余额打开补给，点击「＋」直接请求金币视频，无二次确认。参数在 `rewards.coinsPerVideo`、`coinsDailyLimit`、`coinSupplyThreshold` 中调整。

只接受 `onClose({ isEnded: true })`，禁用 SDK 的兜底分享页。加载最长等待 15 秒；展示请求无响应最长等待 5 秒，释放界面并允许稍后重试。**成功开始播放后等待官方关闭回调**，不自行截断视频或插屏时长。后台预加载不会播放广告，也不计领奖次数。无填充和加载异常退避 30 秒，避免逐帧重复请求。

插屏计数仅从广告启用后新完成的关卡开始，重玩不计数，次数保存到本地。本次领取了通关翻倍，或距离最近任意全屏广告结束不足 **120 秒**，均跳过插屏。提前关闭视频也更新冷却。到触发点而广告未就绪、无填充、频控或发生异常时，本次跳过，不在下一关追补。清理玩法进度不清除广告额度、节奏计数和冷却。

## 运营入口

| 入口 | 参数 / 行为 |
| --- | --- |
| 游戏内「攻略交流」、设置「攻略与交流」 | 打开运营面板，提供当前关卡提示及可用的运营动作 |
| 游戏圈攻略交流 | `community.gameClubOpenlink`：本游戏 MP 后台「游戏内打开」的 openlink |
| 卡关求助与问题反馈 | `community.helpOpenlink`：具体求助帖或话题 openlink；留空时使用游戏圈首页 |
| 通关页「推荐游戏」、运营面板的推荐 | 微信官方普通推荐组件；`community.recommendationEnabled` 控制。使用官方通用常量，不需要填广告 ID |
| 分享到游戏圈推荐 | `community.circleRecommendationOpenlink`：本游戏 MP 后台「游戏内推荐」参数；与普通推荐分开 |
| 分享当前关卡给好友 | 沿用现有分享图、关卡参数和解锁校验；微信好友与朋友圈菜单保留 |

玩家主动点击后打开运营页面，不用推荐、点赞或评论换取金币和爱心。普通推荐状态只根据官方 `destroy` 回调中的 `isRecommended` 保存；未知状态不伪造推荐成功。老基础库通过成功的 `show()` Promise 和返回后的画布操作兼容关闭流程。运营页面打开失败或 15 秒无显示事件时释放状态，保持原关卡、金币和镜面布局。

全屏广告与运营页面共用展示互斥；进入原生页面暂停背景音乐，关闭后恢复。未配置圈子参数时隐藏相应动作，不跳转到 block-escape。

## 后续提供这些内容即可配置

1. 本游戏的激励视频 ID：爱心、金币、提示、翻倍；可以先提供一个共用 ID。
2. 插屏 ID；选关页原生模板 ID（可以各自单独留空）。
3. 本游戏游戏圈后台的「游戏内打开」参数。
4. 可选：求助帖 openlink、「游戏内推荐」参数。

填入 JSON 后重新构建，不需要改玩法代码：

```bash
npm run verify:operations
npm run build:wechat
```

`npm run build:wechat` 生成本地 `dist/wechat`；如需同步开发者工具和体验预览，沿用项目的 `make wechat`。

## MP 后台运营准备

在本游戏的游戏圈创建官方号，配置管理员，然后准备真实游戏内容。建议首批官方帖为：

1. 《光线急转弯新手必看：旋转镜面、按住发射》
2. 《卡关求助：留下关卡号与光路截图》
3. 《解题技巧：从接收器反推光路》
4. 《分光器、集光器与传送门的用法》
5. 《问题反馈与版本更新记录》

把新手说明和求助帖置顶，求助帖的 openlink 填入 `helpOpenlink`。按参考会话的运营思路，邀请真实试玩者从游戏内进入圈子阅读、求助和交流，再在后台查看官方帖计数、内置圈子活跃与流量主资格。

「每周精选内容」在 MP 后台选择内容并安排推广，客户端无须额外接口；这次没有替你发布帖子、开通广告位或创建后台推广。

## 事件与验收

客户端预留 `wx.reportEvent`：

| 事件 | 字段 |
| --- | --- |
| `laser_rewarded_ad` | `stage`、`screen`、`placement`、`action`、`adunit`；实际发奖额外带 `amount` |
| `laser_interstitial` | `stage`、`screen`、`action`、`adunit` |
| `laser_community` | `stage`、`screen`、`target`、`action` |

激励视频 `action` 包括 `request`、`show`、`complete`、`cancel`、`error`、`unavailable`、`reward`。`complete` 表示 SDK 明确完成，`reward` 表示游戏实际发奖。客户端入口点击与广告素材点击不是同一指标；收入查看流量主后台。需要自定义分析时，在本游戏 MP 后台登记事件名与对应字段；客户端代码不会自动创建后台报表。

`npm run verify:operations` 覆盖奖励、重复 / 迟到回调、加载与展示超时、额度、插屏节奏、全屏互斥、运营页面关闭、模板尺寸及 200 个关卡提示。开发服务器的 `/tools/visual/operations.html` 提供配置 / 留空、常见手机尺寸和广告完成 / 取消的模拟 SDK 回归页，不进入正式构建。

提供真实配置后，真机检查四个视频入口的完成与取消、断网重试、插屏关闭后的继续、模板不遮挡关卡、圈子与推荐返回后的状态；本地模拟检查不代表真实广告已填充、产生收入或后台已开通。

`npm run verify:economy` 检查金币购买、起始储备与旧档、重玩、自然恢复、金币广告日限与储备门槛，并输出不同失误率的规划模拟。

本次类型检查、广告 / 运营逻辑回归、分享与教程回归及 Web / 微信构建通过；浏览器界面模拟在 390×844、360×640、375×812 尺寸下验证了领取、取消和结算继续。额外的微信包隔离 Worker 启动模拟中，标准 WebGL2 场景完成了加载和原生触摸开始，后续批量场景及单独的 WebGL1 尝试出现超时，这项未计为通过，也不能据此确认微信真机的启动兼容性。
