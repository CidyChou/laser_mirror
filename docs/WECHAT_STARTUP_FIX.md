# 2026-10-19 微信启动页故障检查

审核截图停留在微信系统启动页，没有进入项目自己的加载页。未获取审核手机的运行日志，也没有原始上传包，因此不能据此认定审核现场的唯一原因。

## 可复现的代码问题

旧版 `MiniGamePixiAdapter` 将所有 Pixi 画布创建为 `type: '2d'` 的原生离屏画布。Pixi 8.19 用同一画布工厂进行 WebGL 能力探测，原生 2D 画布无法提供 WebGL，于是错误降级到 Canvas2D。Canvas2D 渲染器又通过浏览器的 `HTMLCanvasElement` / `OffscreenCanvas` 构造器识别画布，原生环境没有这些构造器时，将主画布资源替换为新的离屏画布。此时初始化可成功，实际渲染没有送往屏幕，原有入口的异常捕获也不会触发。

保留修改前本地 `dist/wechat/game.js`，在严格模拟上述 API 边界的隔离环境中确认：选择 `2d`，显示画布资源被替换，显示画布绘制次数为 0。该本地产物不能直接视为平台上已上传的 1.1.1 包。

## 修正

- 入口先创建上屏画布；Pixi 工厂使用允许首次选择上下文类型的原生 `createCanvas()`。
- 小游戏只选择 WebGL 渲染器，兼容 WebGL1/2，避免误入依赖浏览器画布类型的 Canvas2D。
- 根目录工程补齐 `miniprogramRoot: dist/wechat/`，避免将源码目录当作运行包目录。
- `game.js` 独立于引擎，加载 `game-runtime.js`；记录启动阶段，捕获模块及异步错误，20 秒仍未就绪时提示并保存诊断信息。
- 构建生成 `build-info.json`，含时间、提交、修改状态和运行脚本 SHA256。

## 验证范围

- 类型检查、启动专项检查、Web/微信构建通过，微信包约 2.79 MiB。
- 打包脚本在隔离环境中执行，隐藏 DOM、浏览器画布构造器及 Performance API，并按原生规则限制离屏画布类型。
- WebGL1/2 × 正常/缺失图片，共 4 种场景均保留主画布、发生实际 GPU 绘制、原生触摸点击开始后达到 `playing`，GL 错误码为 0。
- 验证导入错误、异步失败、超时、模块级 `wx` 绑定和诊断去重。

## 2026-10-23 安卓分享启动补充

用户报告已发布版本在 iPhone 15 Pro Max / 微信 8.0.75 上正常，在朋友的“荣耀6”上停在微信启动页。提供的视频在退出游戏前一直未出现本项目的加载页，无法据此区分包下载、原生 JS 执行和首帧渲染。完整机型、安卓/微信版本及失败日志未提供；不能将“荣耀6”直接认定为某款旧机型，也不能确认它与本次复现条件一致。

发现并修正以下可复现的启动失败：

- 原启动器在安装诊断前直接读取 `globalThis`，缺少该全局对象时连错误记录都不会执行。现在先解析 `GameGlobal` / 原生全局，再提供别名。
- Vite 的语法降级不提供基础 API；首个 `LevelRepository` 就使用 `flatMap`。增加 ES5 语法的前置兼容脚本，仅在缺失时提供 `flatMap`、`Object.entries/values`；微信产物语法目标下调为 ES2017。
- 原生 `getContext('webgl2')` 若抛异常，Pixi 原逻辑不会继续试 WebGL1。现在捕获不支持的上下文类型并继续回退。
- 原生音频创建若达到限制或抛异常，原逻辑会在游戏构造阶段退出。现在以静音继续启动。
- 增加首帧阶段记录及启动期间原生错误/未处理 Promise 诊断；支持时通过微信实时日志记录阶段、耗时、机型、系统及微信/基础库版本。未提供实时日志 API 时不影响启动。

实际打包产物的 7 个隔离环境检查通过：WebGL1/2 × 正常/缺图，外加缺失全局/API、WebGL2 抛异常、音频抛异常。全部从新玩家打开 `level:57` 分享参数开始，均保留主画布、有 GPU 绘制并通过原生触摸达到 `playing`，GL 错误码为 0。启动专项、分享、音乐、类型检查通过。上述结果是兼容条件模拟，不是荣耀手机真机验证，线上版本也不会随本地构建自动更新。
