# 章节挑战

每章第10关通关后追加一个独立的动态光路挑战，共13关。原来的1–130关全部保留原编号、原名称和原布局；例如顺序为“第10关 → 第1章挑战 → 第11关”。`verify:time`会检查原130关的完整摘要，防止挑战再次覆盖主线。

## 操作与存档

- 神之手：光束正式发射后可以直接调整非固定镜、分光器和聚合点；每次成功调整消耗1次，每次重新发射时恢复关卡配置的次数。
- 挑战关沿用普通关的加速曲线，但整体速度为普通关的80%，给换轨和回溯留出更多反应时间。
- 子弹时间暂不在客户端展示，13个挑战的提供次数均为0；底层状态、入口和模拟代码保留，方便后续重新启用。
- 回溯：按挑战关（普通关速度的80%）曲线把全局光路回退2/3/4格，0.55秒倒退动画，然后用2.4秒从15%恢复到正常速度。倒退时不能调整，恢复时可使用剩余的神之手次数。
- 所有光束共享时间线。回滚目标、开关、门、充能、聚合释放和分支，保留玩家旋转后的物体方向。
- 回溯期间不能调整；历史不足、蓄力中或次数耗尽时不能使用回溯。神之手与回溯次数都会在每次发射时重置。
- “结束本次试射”提前结束循环或错误路线，按正常失败结算。每个章节挑战每份存档只有一次免费失败保护。
- 回溯教学在首次实际使用时暂停，确认后扣除次数并开始倒计时。
- 新存档键：`laser-mirror-time-progress-v1`，记录已使用保护的关卡和已看教学。清除游戏进度时一并清除；旧存档自动使用空记录。

## 光路与渲染

`TimeLaserSimulator`按实际碰撞逐段建立路线。物体方向在光束抵达时读取，已经走过的反射不会被重新解释。动态模拟与普通关共用`laserTiming`加速曲线，但挑战关应用80%的速度系数；普通关继续使用原有`LaserSimulator`。

游戏会话以10毫秒现实时间步长推进；技能计时与光路时钟分离。分光和聚合生成独立分支，晶体及聚合器按不同入射方向充能。事件快照保留最大回溯范围，恢复世界状态时不恢复物体朝向或技能次数。

挑战关显示最近六格光路并对尾部做渐隐处理，模拟器同时清理超出显示和回溯范围的旧路线，避免循环光路无限增长。

UI沿用项目Taste Skill：一个清晰描边表示可操作，道具栏显示神之手剩余次数，回溯按钮显示距离与次数，不添加全屏滤镜。回滚反向播放目标、门和聚合反馈，光束按历史距离收回，门与聚合动画使用同一模拟时钟。

## 首版布局与设计调整

|挑战位置|神之手|回溯|开发回放调整次数|
|---|---:|---:|---:|
|10、20后|2|0|1|
|30后|2|2×2格|1|
|40、50、60、70后|1|0|1|
|80后|1|1×2格|1|
|90后|2|1×3格|2|
|100后|3|1×3格|3|
|110后|2|0|2|
|120后|3|1×4格|3|
|130后|4|2×4格|4|

布局通过固定回路产生先后抵达的光脉冲，动态镜面负责在不同阶段选择出口。第10关提前出现一个固定分光器和两个终点，只开放一面镜子操作；第20关再扩展分光路线。这个调整用于消除单终点教学图的静态捷径。

相对原概念稿，第80关的回溯用于复用输入镜，补齐聚合器的第二个方向；第110关采用两面镜子接力，未实现单镜A→B→A的独立谜题。第100、120、130关分别使用三、三、四面动态镜子分配阶段，而不是仅用两面镜子承担所有阶段。它们是当前可玩布局，不能视为原13个概念逐项一比一完成。

验证证明所有静态方向配置无解、规定次数内存在动态通关回放，并且30/60/120 FPS结果一致。挑战关80%速度下的操作窗口已通过自动回放，但仍需真人试玩继续调校难度和节奏；回放次数是已验证的解法上界，不宣称为全局最少调整次数。

## 编辑与验证

GM支持启用章节挑战、配置神之手次数、回溯次数及距离，并在导入/导出时保留内部`timeBoss`字段。普通关源为`src/levels/levels.json`，挑战源为`src/levels/time-bosses.json`；运行时由`LevelRepository`把挑战插在对应第10关之后。开发专用布局构造和操作回放位于`scripts/time-boss-designs.ts`，不进入正式游戏包。

开发校验页：`/tools/visual/time-bosses.html`，提供13关、三种主题、GPU/Graphics切换、自动解法与手动技能操作。默认画面375×812，不读写玩家存档。可使用`pose=bullet|rewind|recover|won`定格。该页面显示构造器的布局，正式游戏读取JSON关卡。

```sh
npm run verify:time
npm run validate:levels
npm run analyze:levels
npm run verify:expansion
npm run verify:optics
npm run verify:mechanisms
npm run verify:render-layout
npm run typecheck
npm run build:all
```

`analyze:levels`对130个普通关运行静态求解，对13个章节挑战运行动态验证。挑战使用专门的回放页。`generate:levels`保持普通130关，并同步后80关到`expansion.json`，不会写入挑战文件。
